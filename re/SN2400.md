# TI SN2400 ("Tigris") charger -- RE of iOS 12.5.5 AppleSN2400Charger (iPhone 6 / n61 / t7000)

Method: static disassembly of `kc.macho` (kext header 0xfffffff007f4f7d0, only `__TEXT_EXEC.__text`
0xfffffff007f4f8a0..0xfffffff007f52b98, 0x32f8 bytes, no symbols). Listing: `re/dis/SN2400.s`
(`llvm-objdump -d --start-address=0xfffffff007f4f8a0 --stop-address=0xfffffff007f52b98 kc.macho | python3 annot.py kc.macho`).
Consumer side (AppleARMPMU kext, 0xfffffff007f422a8..0xfffffff007f4f7d0) is in `re/dis/ARMPMU.s` (only skimmed).
Confidence tags: [V] read directly in disassembly, [I] inferred from usage/strings, [G] guess.
Addresses below are VAs as printed by llvm-objdump on kc.macho (static image VAs; load kc.macho in Ghidra as Mach-O and Go To the VA).

## 1. Bus, DT, GPIO/IRQ  (re/dtree.txt:2356 and 3226)
- Node `tigris` on **i2c1** (SoC i2c@0xa111000, same bus as lm3534 @0x63, mesa-eeprom @0x56, drv2604 @0x5a in hoolock dts). [V]
  - `reg: addr=0x9c400000075` -> 7-bit **I2C address 0x75** (low byte; 0x9c4=2500 upper word is a bus-speed/timing field, same on lm3534). [V]
  - `compatible "charger,sn2400"`, `device_type "usb-charger"`, `AAPL,phandle 81`. IOKit match: IONameMatch `charger,sn2400`,
    provider AppleARMIICDevice (kext plist). [V]
  - `interrupts: [24]`, `interrupt-parent: [73]`. **phandle 73 = the PMU (`pmu,d2186`, i2c0 @0x74, interrupt-controller, #interrupt-cells 1)**,
    NOT the SoC GPIO (phandle 24 is gpio). So the charger INT goes through the D2186 PMU's irq controller (PMU `event_name-gpio1: "charger"`,
    i.e. probably PMU GPIO1). [V for parent, I for GPIO1]. hoolock dts has no PMU irq-controller driver -> use **polling** (see 7).
  - No GPIOs, no reset/enable line, no regulator in the node. No other props.
- Cross refs: PMU node has `function-get_vbus_detect: 81:VBUS()`; top `charger` node (`charger,n88`, ph 139) has
  `function-set_charger: 81:chrg()`, `usb-input-limit-max: 0x7d0` (2000 mA), `charger-sleep-interval 0xe10`,
  `usb-input-limit-calibration: "syscfg/CBAT/0x34,zeroes/0x34"`, `charge-limits`, `boot-adapter-id 0`, `boot-voltage 0`,
  `function-tristar_current: 73:adcI(...)` (PMU ADC, unrelated to Tigris). [V]
- Optional DT props the driver reads (all absent in the dump -> defaults): `pmu-debug` (debug flags -> this+0x98),
  `spread-spectrum-enable` (sets cfg bits [1:0]), `sn2400-vbuslim` (default 0x00048000 = 4.5 V in 16.16 fixed),
  `sn2400-no-limits` (0), `sn2400-plimi` / `sn2400-plim-interval` (default 100), `sn2400-grace-period` (0),
  `usb-input-limit-calibration` (CBAT, 0x34 bytes, only used if version word == 3). [V]

## 2. I2C access primitive [V]
All access is through `AppleARMIICDevice` vtable slot 0x558 with (mode, addrlen=1, &reg, len, buf):
- `readReg(reg,&v)`  @0xfffffff007f50b00: mode 1, write 1 byte (reg) then read 1 byte (repeated start).
- `writeReg(reg,v)`  @0xfffffff007f50a2c: mode 2, `[reg][v]` (plain SMBus write byte).
- multi-byte: events read = reg 0x04, 3 bytes; mask write = reg 0x01, 3 bytes (auto-increment); accum read = reg 0x15, 8 bytes.
No chip-ID/revision read anywhere; no reset write. Registers are 8-bit.

## 3. Register map (as far as recoverable)
| reg | dir | meaning | conf |
|---|---|---|---|
| 0x01..0x03 | W (3B burst) | **event mask** 1/2/3; bit=1 = masked/disabled (driver keeps shadow at this+0xb9..0xbb and writes it raw) | V (polarity: shadow semantics I) |
| 0x04..0x06 | R (3B burst) | **event status** 1/2/3; driver computes `active = ev & ~mask`. Sticky/clear-on-read presumed (handler re-reads reg 6 up to 3x to debounce bit2) | V read, I clear-on-read |
| 0x07 | R | **status**. bit0 + bit2 returned by getChargerState (bit0 ~ VBUS/charger present, bit2 ~ charging/limiting, exact names unknown); bit5 = USB-detect (BC1.2) done -> triggers "copyDetectStatus" notify; bit7 (sign) = HDQ/BMU-side busy (checked in setHDQInterfaceGated) | V which bits are tested, G names |
| 0x08 | R | bit0 = "input power limited" status (used by `_isPowerLimited` together with reg6 bit2) | V/I |
| 0x09 | R/W | **INPUT CURRENT LIMIT**: `mA = 90 + 10*code`, code 0..191 (0xBF = 2000 mA). Hardware can reduce it itself: IRQ handler reads it back and, if 0 on ev1 bit6, tells PMU "limit dropped to 90 mA" | V |
| 0x0d | W | `code = min(mA,2550)/10`. Written by Function slot 0xf8 (0xfffffff007f51ff4). Almost certainly **charge (battery) current limit**, 10 mA/LSB (0 = 0) | V write, I meaning |
| 0x0e | R | `mA = 10*val` (Function slot 0x118 @0x...5211c) -- charge-current / termination readback | V, G name |
| 0x0f | R | `mV = 3000 + 10*val` (slot 0x120 @0x...52158) -- charge-voltage readback (e.g. 4350 mV = 135). Never written by iOS | V, G name |
| 0x10 | R/W | **config**. Shadow `_cfg` (this+0xd0) init = 0x04; `|= 0x03` if DT `spread-spectrum-enable`. bits[1:0] = spread spectrum, bit2 = always 1 (normal/enable), **bit3 = suspend/Hi-Z input** (set with bits[1:0] cleared when mA==0) | V values, I bit names |
| 0x11 | W/R | **ADC control**: write `(chan&0xE)|0x10` (bit4 = start), poll until bit4 clears; also written =0x01 after reading accumulators (latch/clear) | V |
| 0x12 | R | ADC result, 8 bit | V |
| 0x15..0x1c | R (8B) | two 18-bit accumulators: `(b0<<10)|(b1<<2)|(b2&3)` and `(b3<<10)|(b4<<2)|(b5&3)` (+6/7 unused?) -> published as `vbus_accum` / `ibus_accum` sensors | V layout, I names |
| 0x1d | R/W | **HDQ-bridge handshake** (gauge "BMU" 1-wire bus shared with charger): write 0x04, poll (10 ms steps, 1 s timeout) until bit5 set, then optionally write 0x06; write 0x00 to release. Timeout -> error 0xe00002d6 | V sequence, I meaning |

Event bits (handleInterrupt @0xfffffff007f4fc54), all [V] for which action, [G] for names:
- ev1 bits 2,4 (0x14): input/adapter change -> notify PMU power source.
- ev1 bits 6,7 (0xc0) or ev3 bit0: re-read reg 0x09 -> report new input limit (see 0x09).
- ev2 bit6 (0x40): "battery alert" -> calls platform fn `function-battery_alert` (unmasked in Function::start only if that fn exists).
- ev2 bits 5,6 (0x60) unmasked while HDQ master mode active (`_mdSoftMask`).
- ev3 bit2 (0x04): input power limited (VBUS collapsing / current-limit loop). On first hit driver sets mask3 bit2 itself (writeReg 3) and
  starts a software timer (default 100 ms interval, `sn2400-plim-interval`) that polls and then re-enables (grace period).

ADC channel select (reg 0x11 bits[3:1]), converted to 16.16 fixed [V formulas]:
- ch0 (code 0): **VBUS**, 25 mV/LSB, no offset (DT `function-vbus_voltage: 81:adcV(0x0)`).
- ch2 (code 2): current, 7.8 mA/LSB (val*78/10000 A) = IBUS/IBAT ("ibus" in power-limit math; 2.0 A full scale).
- ch4 (code 4): 10 mV/LSB, no offset (tjunc? unnamed) [G].
- ch6, ch10: **2500 mV + 10 mV/LSB** = VBAT / VDD_MAIN ("vbat", "vdd_main" sensors both use code 6).
- ch8: affine formula (temperature: "tjunc" sensor uses code 8) [I].

## 4. iOS sequences (verified unless noted)
### 4a. Probe (`AppleSN2400Charger::start` @0xfffffff007f4f920)
1. IOService provider = AppleARMIICDevice; read DT `pmu-debug`; `_cfg=0x04`; if `spread-spectrum-enable` -> `_cfg|=3`.
2. Create IOInterruptEventSource (action 0x...4fc54) on provider IRQ 0 + add to workloop.
3. `enableEvents(0xff,0xff,0xff, enable=0)` => **writeReg burst reg 0x01..0x03 = FF FF FF** (mask everything).
4. Read reg 0x04..0x06 (3B) once to clear pending events.
5. Registers IOService sensors (vbus, ibat, vdd_main, tjunc, vbat, vbus_accum, ibus_accum) = ADC/accum callbacks (0x...4ffb8, 0x...4fff4); looks up
   `function-battery_alert`; `registerService()`.
   **There is NO write to 0x09/0x0d/0x10 at probe. No reset, no ID check.**
6. Interrupt source is enabled by the PMU power source later (via Function start, see 4b).
### 4b. Function object (platform fn `chrg`, class AppleSN2400ChargerFunction, start @0xfffffff007f50fac)
Created by `callPlatformFunction` (@0xfffffff007f50054) when AppleARMPMU resolves `function-set_charger%u`. Reads the DT props in sec 1,
makes two timers (`+0x58` charge timer, `+0x68` power-limit timer). If battery_alert fn exists: `enableEvents(0,0x40,0,1)` (unmask ev2 bit6).
### 4c. Attach / set input limit (`setUSBInputCurrentLimit(mA)` @0xfffffff007f51cc4, helper getInputCurrentSetting @0x...51b0c)
```
if mA == 0 (suspend):  writeReg(0x09, 0x00); writeReg(0x10, (_cfg & ~0x03) | 0x08)
else:                  code = (clamp(mA,90,2000) - 90) / 10      # optional CBAT calibration table if present (syscfg), else raw
                       writeReg(0x10, _cfg)                      # 0x04 (or 0x07 w/ spread spectrum): clears suspend
                       writeReg(0x09, code)
```
The PMU power source (not this kext) picks mA from adapter ID / USB detect (`usb-input-limit-max` 2000, adapter table) and ramps in steps
(`getUSBInputCurrentLimitStep` @0x...51ed0, min step 100 mA [I]).
### 4d. Charge current (slot 0xf8 @0xfffffff007f51ff4): `writeReg(0x0d, min(mA,2550)/10)`. [V write, I meaning]
No setter exists anywhere for a float voltage, termination, precharge or enable bit: **iOS never writes any charge-voltage register**.
### 4e. "Charge timer" / watchdog [V code, I interpretation]
- `_resetChargeTimer(timeout)` @0x...5202c (slot 0x100 @0x...520fc passes timeout=**8 s**; debug prop `ResetChargeTimer` max 59):
  `chargerMode(1)` (@0x...50ca8 -> `_chargerModeGated` @0x...50d58 -> `setHDQInterfaceGated(1,0)` @0x...50790 -> reg 0x07 read + reg 0x1d HDQ
  handshake, see 3) then arm `IOTimerEventSource` for `timeout` s. Timer action `_resetChargerDoneGated` @0x...51374 calls `chargerMode(0)` and clears
  the `_chargerTimeout` flag (+0x50, reported as 3rd out of getChargerState).
- => It is a **software heartbeat** the PMU power source must renew (< 8 s) while charging; on expiry iOS drops back to "BMU master / not charging"
  HDQ mode. **I found no periodic write of any dedicated I2C watchdog register.** The only recurring I2C traffic tied to it is the 0x1d/0x07 HDQ
  handshake. A hidden hardware WDT (reset of 0x09/0x0d/0x10 to defaults after N s) can NOT be excluded from this driver alone, but nothing in the
  code suggests iOS needs to refresh anything to keep Iin programmed (it writes 0x09 only on limit changes and reads it back on IRQ).
### 4f. IRQ path
IRQ -> read 0x04..0x06, `active = ev & ~softmask`, dispatch as in sec 3, then `ev` bits are cleared by that read. Power-limit handling (VBUS < 4.5 V
[`sn2400-vbuslim`] and IBUS < backoff limit computed from reg 0x09) is done in software in `_isPowerLimited` @0x...51764 using ADC ch0/ch2.

## 5. Does the chip charge autonomously? What must Linux do?
Evidence for "yes, once Iin is non-zero": (a) iOS never writes charge enable / voltage / termination; the only control knobs are Iin (0x09),
Ichg? (0x0d), cfg suspend bit (0x10 b3), HDQ ownership (0x1d). (b) Voltage is read back (0x0f), not programmed -> fixed/OTP. (c) iBoot already
programs the adapter state before the kernel (DT `boot-adapter-id`, `boot-voltage`).
Caveat (important): reset/boot defaults of 0x09, 0x0d, 0x10 are NOT recoverable statically. Drain symptom is consistent with the chip sitting at a
low default Iin (code 0 = 90 mA, or ~100/500 mA SDP) / low Ichg while a running A8 + display draws > that, or with a Hi-Z/suspend state left by
iBoot/pongoOS. So Linux must programme Iin explicitly.
**Minimum viable (all [I], derived from verified iOS writes):**
```
read  0x07                       # sanity: bit0/bit2 reflect VBUS present; do not continue if I2C NAKs (addr 0x75, i2c1)
write 0x01..0x03 = FF FF FF      # mask all events (iOS does this at probe) -- keep masked if no IRQ wiring
read  0x04..0x06                 # clear stale events
write 0x10 = 0x04                # normal mode, clear suspend (0x07 to also enable spread spectrum)
write 0x09 = 0x29 (500 mA)       # USB host (SDP);  0x5B=1000, 0x8D=1500, 0xBF=2000 mA for a wall charger. code=(mA-90)/10
write 0x0d = 0x64..0xC8          # 1000..2000 mA charge current (10 mA/LSB); start with 0x64
```
Then re-write 0x09/0x10 every few seconds from a poll loop and read 0x09 back (chip may self-reduce to 0 -> 90 mA on input collapse).
Do NOT go above what the source supports (VBUS < 4.5 V => back off, ADC ch0 reads VBUS: code*25 mV).
Unknowns that may still block charging: PMU (D2186 @i2c0 0x74) state (charger GPIO1/VBUS detect, battery-present logic), Hi-Z/ship-mode state
left by pongoOS, and whether HDQ handshake (reg 0x1d) is required before the gauge/charger stop reporting "no master when charging".
Experiment plan (no hardware now): first boot with a userspace `i2cdump -y 1 0x75` of 0x00..0x1f BEFORE writing anything, to capture the
iBoot-programmed values of 0x07,0x08,0x09,0x0d,0x0e,0x0f,0x10; then write 0x09 only and watch ADC (reg 0x11/0x12) ibus/ibat.

## 6. HDQ bridge note (for the fuel gauge)
Strings: "BMU Master when discharging", "No Master when charging", `setHDQInterfaceGated`, platform fn `HDQm`. The battery gauge (Apple "BMU") sits on
a 1-wire HDQ bus that Tigris bridges; `chargerMode` 0/1 flips ownership via reg 0x1d + ev2 bits 5/6. The kernel tree has
`drivers/power/supply/bq27xxx_battery_hdq.c`, but it assumes a w1/HDQ master; Tigris would need to expose reg 0x1d protocol as a w1 master. Out of
scope for "just charge" but needed for a real battery percentage.

## 7. Closest mainline driver
**None is register-compatible** (checked drivers/power/supply: bq24190, bq2415x, bq24257, bq25890, bq256xx, bq25980, rt9455, max77*...).
Layout mismatch examples: bq24190 reg0=IINLIM(3-bit table 100..3000), reg2=ICHG(64 mA), reg4=VREG, reg5=WATCHDOG; bq25890 reg0=IINLIM (50 mA step,
100 mA offset), reg2/3 ADC+chg cfg, 0x0E-0x11 ADC; SN2400 has 3 mask + 3 event regs at 0x01-0x06, 10 mA IINLIM @0x09, ADC ctrl/data @0x11/0x12,
no VREG/WATCHDOG/termination regs. Recommendation: write a small new `sn2400-charger.c` (regmap_i2c, 8-bit regs, use `power_supply` with
`CONSTANT_CHARGE_CURRENT`, `INPUT_CURRENT_LIMIT`, `ONLINE`, `VOLTAGE_NOW`(ADC ch0/ch6)), **skeleton copied from bq24190_charger.c** (IRQ/workqueue,
devm power_supply, DT) or bq25890_charger.c (ADC/IINLIM style). Evidence for choosing them is structural only, not register-level.
Interrupt: no PMU irq-controller in hoolock -> `INIT_DELAYED_WORK` poll (2-5 s) refreshing 0x10/0x09/0x0d is the practical minimum.
Suggested DT (hoolock t7000-n61.dts, under `&i2c1`): `charger@75 { compatible = "apple,sn2400"; reg = <0x75>; };`
